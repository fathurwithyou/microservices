# M2 — Scalable Distributed System

This document covers the M2 additions. M1 remains the baseline under `docs/IF4031_M1_Laporan.md`.

## Architecture

```text
Client / Media / Field / Ops
        │ HTTP
        ▼
   Client API
        │ gRPC
        ▼
   Aggregator (3 replicas) ── CockroachDB (4 nodes, RF=3)
        │                         │
        │                    leader lease
        ▼
     RabbitMQ
   ├── dashboard-consumer
   ├── notifier-consumer
   ├── critical-notifier
   └── portal-consumer

satellite-ingestor ──► Aggregator
coastal-ingestor   ──► Aggregator
```

## New components

| Component | Responsibility | State |
|---|---|---|
| `satellite-ingestor` | SSE feed, durable offset, fire clustering | offset, detections, fire mapping |
| `coastal-ingestor` | sensor polling over `/v1/observations`, contract validation, cursor, quarantine, circuit breaker | quarantine, last good |
| `sensor-pantai` | vendor sensor image, pinned by digest, exposes `/v1/stations` and `/v1/observations` | cursor in `/data` |
| `critical-notifier` | separate critical queue for field alerts | RabbitMQ |
| CockroachDB | Aggregator canonical store | 4 nodes, RF=3, TLS; no node holds every range |
| PostgreSQL | Auth service only | separate auth_db |

## New contracts

- Sources: `SATELIT`, `SENSOR_PANTAI`.
- Hazard types: `WILDFIRE`, `COASTAL`.
- Scope: `field-reports:write`.
- Client API: `POST /field-reports` → `202 Accepted`, `GET /analytics` for the dashboard, `GET /coastal/latest` for the last stored coastal event plus feed status.
- Hazard listings carry `partial` and `unavailable_units` when a store unit is unreachable.
  A dead store node counts only while it still holds a replica of
  `aggregator_db`; once its ranges are re-replicated, answers are complete
  again even before the node is decommissioned.
- `GET /hazards` pages with `page_token` (keyset on `occurred_at desc,
  hazard_id desc`); `next_page_token` is empty after the last page.
- Aggregator internal gRPC: `SubmitHazard` for satellite and coastal ingestors.
- Aggregator Audit API:
  - `GET /internal/audit/events`
  - `GET /internal/audit/checksum`
  - `GET /internal/audit/location`
  - `GET /internal/audit/distribution`: per store node, the `hazard_events`
    range replicas, leases, and replica bytes it holds, plus
    `holds_all_ranges` (P1.1 evidence)
  - `GET /internal/audit/unprocessed`
  - `POST /internal/ops/replay?source=PVMBG` (Ops token)
  - `GET /internal/ops/failures?source=&limit=&cursor=` and
    `GET /internal/ops/failures/{message_id}` (Ops token): the listing
    returns metadata and `payload_bytes` only (bodies can be up to 8 MiB);
    the single-message endpoint adds the raw bytes (`payload` when valid
    UTF-8, else `payload_base64`). Both show the original `reason` and the
    latest automatic retry outcome as `last_error`. The audit listing
    `/internal/audit/unprocessed` never exposes payloads.
- Analytics adds a dashboard-only `category` (`TSUNAMI` = SEISMIC event with
  `potential_tsunami=true` or a correlated `warning_id`). The canonical
  HazardEvent keeps `hazard_type=SEISMIC` as the M1 mapping requires, and
  categories are exclusive, so their sum equals the Audit API event count.

## Sensor Pantai integration

The vendor image is pinned in `deploy/kustomize/base/sensor-pantai.yaml` and in
the Compose `m2` profile. Its contract is:

- `GET /v1/stations` returns the station registry with coordinates and province.
- `GET /v1/observations?cursor=...` returns `{generated_at, items, next_cursor}`.
  Items carry `observation_id`, `station_id`, `observed_at`, `quality`,
  `wave_height_m`, `sea_level_anomaly_m`, and `critical`.

`coastal-ingestor` walks pages, keeps the tail cursor in memory, deduplicates
the tail page by `observation_id`, maps coordinates and `area_name` from the
station registry, and maps `critical: true` to `AWAS` (otherwise `NORMAL`).
Quality values other than `ok` are quarantined with a reason. The documented
mapping is an assumption because the vendor contract document has not been
distributed yet.

## Failure inbox (P3)

Classification of a message that cannot become a HazardEvent:

| Case | Example | `retryable` | `status` | Recovery |
|---|---|---|---|---|
| Schema violation | renamed/retyped/missing field (`mode: breaking`) | false | `parked` | fix mapping, then Ops replay |
| Undecodable record | one array element with invalid UTF-8 or that is not an object | false | `parked` | other records in the response are ingested and the cursor advances; fix the partner data, record kept for inspection |
| Undecodable response | truncated JSON, nesting > 10000, body > 8 MiB | false | `parked` | window is re-polled automatically; body kept for inspection |
| Missing reference data | `volcano_id` absent from `volcano_reference` | true | `retrying` | automatic retry once the row exists; parked after max attempts |

A response that cannot be split into records never advances the poll cursor,
so valid records in the same window are fetched again on the next poll. A bad
record inside an otherwise valid array is parked on its own, so one
persistently corrupt record cannot block the feed. Replay skips undecodable
bodies without counting them toward `limit` (paging past them), stops at the
first other failure, and processes records in arrival order. The automatic
retry worker runs only on the ingestion leader, revalidated against the
database clock before every message.

PVMBG mock modes (`POST /admin/schema-version`, header `X-PVMBG-Admin-Key`):

```text
{"mode": "breaking"}                      // incompatible schema until reset
{"mode": "truncated", "count": 1}         // also deep_nesting, invalid_utf8, oversized
{"mode": "normal"}                        // back to schema v1, well-formed
{"enabled": true}                         // additive v2 (confidence_level), as in M1
```

Field reports: `POST /field-reports` validates `hazard_type`
(SEISMIC/VOLCANIC/WILDFIRE/COASTAL, case-insensitive), `severity`, RFC3339
`occurred_at` with timezone, and coordinate ranges. Client mistakes return
400 with the reason; only real upstream failures return 5xx.

## Historical earthquake catalog

`import-catalog` loads a JSON array or newline-delimited JSON file through the
same seismic mapping used by the live BMKG poller. Each row uses
`event_id`, `magnitude`, `depth_km`, `epicenter_lat`, `epicenter_lon`,
`region_name`, `occurred_at`, and `potential_tsunami`.

```bash
AGGREGATOR_DATABASE_URL=... STORE_DRIVER=cockroach \
  go run ./services/aggregator/cmd/server import-catalog -file catalog.ndjson
```

The command inserts in one batch and skips rows that already exist by
`(source, source_ref_id)`. It does not emit outbox messages for historical rows.

```bash
  --for=condition=complete job/cockroachdb-certs --timeout=180s

  --for=condition=complete job/cockroachdb-bootstrap --timeout=300s

```

The certs Job issues one client certificate per store owner; the bootstrap
Job initialises the cluster and creates one database and SQL user per owner.
See `deploy/kustomize/README.md` for the ownership table.

## Storage ownership

Each store has exactly one owner, enforced by the platform:

- CockroachDB: `aggregator_db`/`aggregator`, `satellite_db`/`satellite`,
  `coastal_db`/`coastal`. Privileges are granted to the owner only; `public`
  loses `CONNECT`. Each pod mounts only its own client certificate, so it can
  authenticate only as itself. Compose applies the same SQL (insecure mode
  skips authentication but still enforces privileges).
- PostgreSQL: `auth_db` for the auth service only.
- NetworkPolicies admit database traffic only from the owner pods.

## Observability endpoints

Every HTTP/health server exposes `/metrics`. Aggregator and Client API emit
server spans; gRPC calls between Client API, Aggregator, and Auth are traced.
The Compose stack leaves tracing disabled unless an OTLP endpoint is supplied.

## Known limits

1. `satellite-ingestor` and `coastal-ingestor` use durable pgx state when their
   `*_DATABASE_URL` is set; the in-memory adapter remains the test/fixture fallback.
   Each service keeps its own goose version table (`satellite_goose_db_version`,
   `coastal_goose_db_version`); a shared `goose_db_version` previously hid the
   coastal tables.
2. Field reports are durably accepted and an asynchronous worker moves them to
   `processed`; the downstream side effect is still a no-op.
3. The sensor cursor is persisted in `coastal_cursor` after every committed batch.
4. `satellite-ingestor` and `coastal-ingestor` use database leases; with two
   replicas only the lease holder opens the feed / polls the sensor and writes
   state. A new coastal leader resumes from the committed cursor, and a leader
   whose lease expired (freeze) drops its batch before writing.
5. Park/replay covers PVMBG and BMKG mapping failures and undecodable responses.
6. Critical coastal events are routed to `hazard.events.critical` and consumed by
   `critical-notifier`; end-to-end latency is not measured yet.
7. Client API reserves 80% of in-flight capacity for Field Team/raw-scope clients
   and 20% for Media; Media receives 429 with `Retry-After` when its class is full.
8. CockroachDB cert rotation is manual.
9. The cluster overlay expects a `local-path` StorageClass.
10. Metrics are exposed at `/metrics`; OTLP tracing activates when
   `OTEL_EXPORTER_OTLP_ENDPOINT` is set. The demo stack points it at the
   collector in `observability.yaml`.

These limits are tracked in the M2 implementation plan. They must be closed
before the final demo.
